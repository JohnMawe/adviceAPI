API Overview

MotiveSynk API is a RESTful API for integrating motivational content into your applications. It provides motivational content in three media types text, audio, and visual and supports filtering by mood.
Use the API to deliver personalized motivational content and inspire your users in your own way.

Get Started

Welcome to the MotiveSynk API. This guide will help you make your first API request and start integrating motivational content into your application.

1. Get your API key

To access the MotiveSynk API, you need an API key.
You can request an API key from your Developer Dashboard. 


API key
msk_live_xxxxxxxxxxxx

Keep your API key private. Do not expose it in frontend JavaScript, public repositories, or client-side applications.

2. Set the API key

Include your API key in the Authorization header of every request. 


Authorization: Bearer YOUR_API_KEY

For example:


GET /api/v1/motivations
Authorization: Bearer msk_live_xxxxxxxxx

3. Make your first request

Once you have your API key, you can request a motivation:


GET /api/v1/motivations

Example using curl:


curl -X GET "https://api.motivesynk.com/api/v1/motivations" \ -H "Authorization: Bearer YOUR_API_KEY"

4. Receive a response

A successful request returns JSON:


{
    "id": "ms_98432",
    "mood": "procrastinating",
    "core_concept": "Action precedes clarity. Do not wait for inspiration to move.",
    "resources": {
        "text": [
            "Stop thinking",
            "Start small",
            "Momentum builds after you begin"
        ],
        "image_url": "https://motivesynk.com/...",
        "audio_url": "https://motivesynk.com/...",
        "author": "Unknown",
        "tags": [
            "discipline",
            "focus",
            "action"
        ]
    }
}

5. Start exploring the API

Once your first request works, you can explore the available endpoints to:

  • Retrieve motivations
  • Filter motivations by mood
  • Choose specific media types
  • Retrieve a motivation by ID
  • Build personalized motivational experiences

Authentication

The MotiveSynk API uses API keys to authenticate requests. An API key identifies your application and allows you to access protected API endpoints. You must include a valid API key with every request that requires authentication.

API Key

You can obtain your API key from your MotiveSynk Developer Dashboard. Your API key should be kept private and should never be exposed in client-side code, public repositories, or other publicly accessible locations.

Example:


msk_live_xxxxxxxxxxxxxxxxxxxxxxxxx

Keep your API key secure. Anyone with access to your API key may be able to make requests on behalf of your application.

Authentication Header

Send your API key using the Authorization HTTP header with the Bearer authentication scheme. 


Authorization: Bearer YOUR_API_KEY

For example:


GET /api/v1/motivations Authorization: Bearer msk_live_xxxxxxxxxxxxxxxxx

The API key should be included in every authenticated request.

Example Request

cURL


curl -X GET "https://api.motivesynk.com/api/v1/motivations" \ -H "Authorization: Bearer YOUR_API_KEY"

Python


import requests

url = "https://api.motivesynk.com/api/v1/motivations"

headers = {
    "Authorization": "Bearer YOUR_API_KEY"
}
response = requests.get(url, headers=headers)
print(response.json())

Security Best Practices

Follow these practices when working with your MotiveSynk API key:

  • Never commit your API key to Git.
  • Never put your API key directly in frontend JavaScript.
  • Store your API key in an environment variable.
  • Don't share your API key through screenshots, messages, or public documentation.
  • If you believe your API key has been compromised, revoke it and generate a new one.

For example, instead of:


API_KEY = "msk_live_123456789"

Use an environment variable:


import code
API_KEY = os.getenv("MOTIVESYNK_API_KEY")

Then:


                MOTIVESYNK_API_KEY=msk_live_xxxxxxxxxxxxxxxxx

Base URL

The MotiveSynk API uses a common base URL for all API requests. All API endpoints are built by adding an endpoint path to this base URL.

API Base URL

Base URL without endpoint returns the current status and actual version of MotiveSynk API

For Example:

Request URL:


https://api.motivesynk.com/api/v1

Response


{
    "version": "1.0.0",
    "status": "online"
}

URL Structure

The general structure of a MotiveSynk API URL is: 


BASE_URL + ENDPOINT

For example:

Base URL: 


https://api.motivesynk.com/api/v1

Endpoint: 


/motivations

Complete URL:


https://api.motivesynk.com/api/v1/motivations

API Versioning

The MotiveSynk API includes its version in the URL. The current API version is v1. 


https://api.motivesynk.com/api/v1

Including the version in the URL allows future versions of the API to introduce changes without unexpectedly breaking applications using an older version.

Example of endpoints include:


GET /motivations

Retrieves available motivational content.


GET /motivations/{id}

Retrieves a specific motivation using its ID.


GET /motivations?mood=focused

Complete Request Example

A request to retrieve motivations would use:


GET https://api.motivesynk.com/api/v1/motivations

The API key should be included in the Authorization header as described in the Authentication section.

Endpoint

MotiveSynk API endpoints allow you to access and interact with motivational content. Each endpoint performs a specific operation, such as retrieving motivations, filtering content, or retrieving a specific motivation.

All endpoints are relative to the API Base URL:


https://api.motivesynk.com/api/v1

HTTP Methods

The API uses standard HTTP methods to indicate the type of operation being performed.

GET - Retrieve information from the API.
POST - Create new information or resources.
PUT - Update an existing resource.
PATCH - Partially update an existing resource.
DELETE - Remove a resource.

Available Endpoints

Get Motivations

GET /motivations

Retrieves a list of available motivational content.

Example:


GET /motivations

Complete URL:


https://api.motivesynk.com/api/v1/motivations

Get Motivation by ID

GET /motivations/{id}

Retrieves a specific motivation using its unique ID.

Example:


GET /motivations/ms_98432

The {id} value should be replaced with the ID of the motivation you want to retrieve.

Pagination

GET /motivations?page={page-number}

GET /motivations?limit={limit-per-page}

By default, the GET /motivations endpoint returns 15 motivations per page. You can use the page and limit query parameters to control pagination. The page parameter allows you to navigate between pages, while the limit parameter controls the number of motivations returned per page.

For example:


GET /motivations?page=2&limit=25

Filters

Available filters include:

  • mood
  • media_type

Filter Motivations by Mood

GET /motivations?mood={mood}

Retrieves motivations that match a specific mood.

Example:


GET /motivations?mood=focused

You can replace focused with another supported mood.

Suported mood may includes:

  • Focused
  • Procrastinating
  • Weak
  • Sad
  • Energetic

Filter by Media Type

GET /motivations?media_type={type}

Retrieves motivations based on the requested media type.

Example:


GET /motivations?media_type=audio

Supported media types may include:

  • Text
  • Audio
  • Visual

Combine Filters

Multiple query parameters can be used to further refine the results.

Example:


GET /motivations?mood=focused&media_type=audio

This request retrieves audio motivations associated with the focused mood.

Endpoint Parameters

Endpoints can accept different types of parameters.
Path parameters are included directly in the URL.

Example:


/motivation/{id}

Query parameters are added after ? and are used to filter or customize a request.

Example:


/motivations?mood=focused

Multiple query parameters are separated using &.

Example:


/motivations?mood=focused&media_type=audio

Authentication

Endpoints that require authentication must include a valid API key in the Authorization header.

Example:


Authorization: Bearer YOUR_API_KEY

Refer to the Authentication section for more information about obtaining and using an API key.

Endpoint Summary

GET /motivations - Retrieve motivations.
GET /motivations/{id} - Retrieve a specific motivation.
GET /motivations?mood={mood} - Filter motivations by mood.
GET /motivations?media_type={type} - Filter motivations by media type.
GET /motivations?mood={mood}&media_type={type} - Combine multiple filters.
GET /motivations?page={page-number}&limit={limit-per-page} - Controls pagination.

Request & Response

The MotiveSynk API uses standard HTTP requests and JSON responses. Requests are sent to the appropriate API endpoint, while responses contain the requested motivational content or information about an error.

Request Structure

An API request generally consists of:

  • HTTP method
  • Endpoint URL
  • Headers
  • Query parameters or path parameters, when required
  • Request body, when required

Example:


GET /api/v1/motivations
Authorization: Bearer YOUR_API_KEY

Request Headers

Authenticated requests must include the API key in the Authorization header. 


Authorization: Bearer YOUR_API_KEY

The API uses JSON for request and response data. When sending JSON data in a request body, specify the content type: 


Content-Type: application/json

Query Parameters

Query parameters can be used to filter or customize the requested data.

Example:


GET /api/v1/motivations?mood="focused"

Path Parameters

Some endpoints use parameters directly in the URL.

Example:


GET /api/v1/motivations/{id}

A request for a specific motivation could look like: 


GET /api/v1/motivations/ms_98432

Request Body

Endpoints that create or update resources can receive data through a JSON request body.

Example:


{
    "mood": "focused",
    "media_type": "text"

The request body should contain valid JSON and follow the requirements defined by the endpoint.

HTTP Status Codes

The API uses standard HTTP status codes to indicate whether a request was successful.

200 OK

The request was successful.

201 Created

A new resource was successfully created.

400 Bad Request

The request contains invalid or missing data.

401 Unauthorized

Authentication is required or the provided API key is invalid.

404 Not Found

The requested resource could not be found.

429 Too Many Requests

The client has exceeded the allowed request rate.

500 Internal Server Error

An unexpected error occurred on the server.

Error Response

When a request fails, the API returns a JSON response describing the error.

Example:


{
    "error": "Invalid API key",
    "message": "The provided API key is invalid."
}

The error field identifies the type of error, while the message field provides additional information about what went wrong.

Errors

The MotiveSynk API uses standard HTTP status codes to indicate whether a request was successful or failed. When an error occurs, the API returns a JSON response containing information about the problem.

Error Response Structure

A typical error response contains an error field and a message field 


{
    "error": "Invalid API key",
    "message": "The provided API key is invalid."
}

The error field identifies the type of error, while the message field provides additional information about what went wrong.

HTTP Error Status Codes

400 Bad Request

The server could not process the request because the request contains invalid or missing data.

Example:


HTTP/1.1 400 Bad Request

{
    "error": "Invalid request",
    "message": "The request contains invalid data."
}

Common causes include:

  • Missing required fields
  • Invalid field values
  • Invalid query parameters
  • Malformed JSON

401 Unauthorized

The request requires authentication, but the API key is missing or invalid.

Example:


HTTP/1.1 401 Unauthorized

{
    "error": "Authentication required",
    "message": "API key is missing."
}

For an invalid API key


{
    "error": "Invalid API key",
    "message": "The provided API key is invalid."
}

Check the Authentication section for information about API keys.

404 Not Found

Example:


HTTP/1.1 404 Not Found

{
    "error": "Not found",
    "message": "The requested motivation was not found."
}

This can occur when a requested resource does not exist or an incorrect endpoint is used.

429 Too Many Requests

The client has exceeded the allowed number of API requests within a specific period.

Example:


HTTP/1.1 429 Too Many Requests

{
    "error": "Rate limit exceeded",
    "message": "Too many requests. Please try again later."
}

See the Rate Limit section for more information.

500 Internal Server Error

An unexpected error occurred while processing the request.

Example:


HTTP/1.1 500 Internal Server Error

{
    "error": "Internal server error",
    "message": "An unexpected error occurred. Please try again later."
}

If you receive this error repeatedly, try again later or contact MotiveSynk support.

Handling Errors

When making API requests, your application should check the HTTP status code before processing the response.

For example:

200 -> Process the response
400 -> Check the request data
401 -> Check the API key
404 -> Check the requested resource
429 -> Wait before sending another request
500 -> Try again later

Best Practices

When handling MotiveSynk API errors:

  • Always check the HTTP status code.
  • Read the error and message fields.
  • Do not expose API keys in error logs or client-side applications.
  • Handle errors gracefully in your application.
  • For 429 responses, wait before retrying.
  • For 500 responses, retry later rather than repeatedly sending requests.

Rate Limit

The MotiveSynk API uses rate limits to ensure fair usage and maintain reliable performance for all applications. A rate limit controls how many requests an application can make within a specific period.

Rate Limit

Each API key has a maximum number of requests it can make within a defined time window.

For example:

100 request per minute
This means an application can make up to 100 requests within one minute using the same API key.
Once the limit is reached, additional requests will be rejected until the rate-limit window resets.

Rate Limit Response

When an application exceeds its allowed request limit, the API returns: 


HTTP/1.1 429 Too Many Requests

Example response:


{
    "error": "Rate limit exceeded",
    "message": "Too many requests. Please try again later."
}

Rate Limit Headers

The API may include headers that provide information about the current rate limit.

Example:


X-RateLimit-Limit: 100
X-RateLimit-Remaining: 25
X-RateLimit-Reset: 60

These headers indicate:

  • X-RateLimit-Limit — Maximum number of requests allowed.
  • X-RateLimit-Remaining — Number of requests remaining.
  • X-RateLimit-Reset — Time remaining before the rate limit resets.

Handling Rate Limits

Applications should detect 429 Too Many Requests responses and avoid immediately sending more requests.
A recommended approach is to wait and retry after the rate-limit window resets.

Best Practices

To avoid unnecessary rate-limit errors:

  • Avoid sending repeated requests unnecessarily.
  • Cache responses when appropriate.
  • Use the appropriate filters when retrieving data.
  • Monitor the rate-limit headers.
  • Implement retry logic with a delay.
  • Avoid sending requests in tight loops.
